HTTP API v2 и съвместимост с v1

Всяка операция извиква съществуващата BulgarianLanguageSession върху един строго идентифициран пакет. GET /api/v2/ връща действителни assembly версии, package provenance и ограниченията на host-а. GET /api/v1/ пази предходната HTTP версия.

Новият v2 договор и host profile са source кандидат. Build, новите тестове, HTTP/resource измерванията и browser проверката за този batch предстоят. R5/R7 не са приети.

GenerateForms(lemma) връща краен набор словоформи по лема от пакета. Продуктивният анализ с AnalyzeWord и DecomposeWord може да намери допустим графов път за незаписано новообразувание. DeriveWords извършва ограничено търсене от основа. Тези операции не изброяват всички възможни новообразувания и не доказват продуктивно покритие само с краен списък словоформи.

Заявки

POST с Content-Type: application/json. Поле text е задължително. Непознати полета се отхвърлят. При колекционните public операции изричният limit от 1–256 се предава директно на API. Без поле limit: GenerateForms използва 128; Lookup, AnalyzeWord и DeriveWords използват Web default 32. Explorer-ът изпраща избрания лимит; началният избор за словоформи е 256 и може да бъде намален.

Лексикални owners и релации

POST /api/v2/lookup-lexical-entries
{ "text": "книга", "limit": 32 }
POST /api/v2/lexical-entry
{ "text": "<точен entryId от първата заявка>" }

metadataAvailable:false означава пакет без annotations. Празни meaning/related при налични annotations са отделен случай. Owners на омоними остават отделни; meanings пазят буквални strings с CR/LF, празни стойности, повторения и ред. Relation groups пазят raw kind и подредени phrases. Resolved phrase съдържа words с exact entryId/form/fullTag references. При несвързваема изходна дума цялата фраза остава на същата позиция с празно words, всички raw Word IDs в unresolvedSourcePhrase и isResolved:false; тя не доказва singleton relation и не участва в текстови съвпадения. relationsComplete отчита тези source gaps за owner, а packageHasUnresolvedRelations за пакета, с coverage.complete:false. Полетата не оценяват значенията или общата езикова пълнота. Null tag не се допълва по предположение. Preview 4 няма annotations и връща явна липса на тези данни.

AnalyzeText добавя lexical с Word owners и оригинални UTF-16 spans. Per-token owner limit е 32 с явен truncated. Срещнат деклариран многословен relation target сочи source owner, relation/phrase occurrence индексите и точните references; не получава значението на source owner. Между думите се допуска whitespace, без пунктуация или newline separators. Полетата се запазват и в двата shared формата.

Текст и отделна заявка

POST /api/v2/find-forms-in-text
{ "text": "Книга, книга и книгите. 📚", "query": "книга" }

Точно изписване означава цял Word token с ordinal, case-sensitive равенство към query. Lemma match използва всички върнати WordReading.Lemma, GraphCandidate.DerivedLemma и MorphologyCandidate.Lemma във всички lanes, включително shorter-ending children. Root Base и supporting donor lemmas не заместват лемата на производната дума. Без DerivedLemma графовият път остава evidence без измислена lemma проекция.

data съдържа действителните queryAnalysis и textAnalysis, всички queryLemmaEvidence и matches с tokenIndex/Start/Length в UTF-16. StoredLemmaMatches изисква речникови readings от двете страни; EvidenceLemmaMatches има поне една хипотеза. Conditional, ambiguity и incomplete са отделни означения. Няма контекстно разрешаване, правописна присъда или втори morphology engine. При click демото показва същия AnalyzeText токен и неговия JSON, защото нов AnalyzeWord може да използва различен work budget.

Отговор и пълнота

HTTP версията се избира чрез route и се връща в apiVersion. Без evidenceFormat v2 използва shared-analyses-v1, а v1 пази raw представянето. На двете версии изричното поле приема raw-v1, shared-donors-v1 или shared-analyses-v1. Форматът е отделен от HTTP версията; непознат формат връща 400 invalid-evidence-format. versions и package посочват действителните версии и хешове.

Raw представянето пази inline public data. Двата shared формата добавят evidenceFormat и donorSets: пълни подредени donor масиви за този отговор. В graph path conditionalSupportingLemmasRef заменя conditionalSupportingLemmas; в морфологичен кандидат supportingLemmasRef заменя supportingLemmas, включително при shorter-ending кандидати. Всяка reference е целочислен индекс от 0 в donorSets. Null/липсващо graph поле остава липсващо; празен масив има reference към празен масив.

shared-analyses-v1 добавя wordAnalyses. Всеки TextAnalysis token пази оригиналните text, kind, start и length, но заменя analysis с analysisRef: индекс от 0 в wordAnalyses или null при липсващ анализ. Таблицата съдържа всяка уникална reference-identical WordAnalysis инстанция веднъж, в реда на първата поява на токена. Различни инстанции не се сливат по дума или нормализиран текст. queryAnalysis остава inline веднъж. Споделянето е HTTP projection върху публичните C# резултати.

Donor споделянето сравнява целите подредени масиви ordinal; еднакви program/tag или брой не са достатъчни. Пълните query-specific списъци, cardinality, self-exclusion, guards, unmet requirements, sources и flags се запазват. Няма donor cap или query-independent donor-cell registry. Разрешаването на references възстановява public резултата; индексите не важат за друг отговор. JSON използва UTF-8 кирилица, като пази escaping на HTML-sensitive и контролни символи; decoded стойностите и UTF-16 offsets са непроменени.

Демото използва v2 default. Подробното evidence и JSON се отварят при поискване; избраният оригинален токен се разрешава към wordAnalyses без копиране, hydration или нов AnalyzeWord. Token JSON остава действителният transport fragment с достъп до целия отговор и двете таблици.

limits съдържа requested, effective, hostMaximum, hostLimitApplied и scope. За операция с входен лимит поисканите 100 остават effective 100; hostMaximum е 256 и hostLimitApplied е false. При пропуснат limit requested е null и effective показва описания HTTP default. AnalyzeText и текстовото сравнение показват собствения си scope с 32; DecomposeWord е scalar evidence. Метаданните /api/v1/ разграничават resultLimit (максимум), defaultResultLimit, generateFormsDefaultLimit, textWordAnalysisLimit и queryAnalysisLimit.

При успешен отговор coverage.hostTruncated е false: host-ът не премахва редове от public резултата. possibleTruncation е true при достигнат лимит на поне една collection; това е отделно от GraphSearchIncomplete. complete е false при kernel limit flag, иначе null (неизвестно). Host-ът никога не превръща липсващо доказателство за пълнота в true. Езикова хипотеза не е речников прочит или правописна присъда.

Успешният language ApiEnvelope във всички версии и формати минава count-only byte preflight преди response headers. Кандидатният host default е 32 MiB (33554432 UTF-8 body bytes), конфигурируем чрез положителен BgLang:ResponseByteLimit. Това е настройка на host-а, не owner-imposed или универсален приемателен таван. Counting sink не пази целия body; допуснатият отговор се сериализира и предава с ограничени write buffers. По-голям резултат връща 413 response-too-large с малък error JSON и coverage: {hostTruncated:true, possibleTruncation:true, complete:false}. Няма частичен 200, clipping на списъци или скрито намаляване на proof. Малкият bounded protocol error е изключен дори при настройка под неговия размер, без recursive byte отказ; фиксираните малки metadata/health отговори също са извън language body cap.

Статуси и изпълнение

200Успешно public извикване; може да съдържа ограничено/непълно evidence.
400Невалиден JSON, поле, text, UTF-16 дължина или limit.
413 / 415Прекалено голям request body или response-too-large при byte preflight / неподдържан Content-Type.
429Над 30 POST заявки за една минута от IP; има Retry-After.
503Не е ready, shutdown, пълна/изтекла опашка или запълнен ограничен IP регистър; има Retry-After.
504Изтекъл 10-секунден cooperative deadline преди headers. Синхронната CPU работа не може да бъде preempt-ната и може да отложи връщането на 504 до действителния си край.
500Неочакван execution failure; без входен текст или stack trace в отговора.

Един queue worker притежава kernel извикването, projection, count preflight, сериализацията и awaited success transfer до действителния край на language callback-а. До 4 заявки чакат, максимум 2 секунди преди започване. Timeout/disconnect не освобождава тази линия преждевременно. Shutdown отхвърля чакащите и изчаква започнатата преди Dispose на сесията.

10-секундният linked cooperative deadline покрива четенето на request body, kernel, projection, count preflight, сериализацията и awaited success transfer; не гарантира доставката през Internet и не прекъсва синхронната kernel работа. Малките фиксирани protocol ErrorAsync отговори (413/504 и други) се изпращат извън queue worker-а и този deadline с RequestAborted; за тях няма безусловен 10-секунден error-transfer timeout. След започнати headers прекъснатият отговор се abort-ва; към вече изпратения JSON не се дописва error tail.

/health/live и /health/ready са отделни от езиковите операции. Listen започва след успешен Open и проверка на manifest SHA-256. Логовете са изключени по подразбиране; няма retained body logs или result cache. IP регистърът пази максимум 1024 entries.

Forwarded/X-Forwarded-* headers се игнорират. Rate limit използва непосредствения peer IP. Публичният deployment трябва да използва Kestrel HTTPS или отделно прегледан proxy trust profile; зад proxy този default ще брои неговия IP като един клиент. Няма CORS или cross-origin достъп по подразбиране.

Text composition — 2026-10-21

AnalyzeText добавя readingInventory, metrics, spelling, profile и properNames и в трите response формата. Пълният exact inventory пази original reading order и duplicates преди показваните първи 32 прочита. Supports сочат original tokenIndex/completeReadingIndex, включително след индекс 31.

metrics съдържа девет описателни брояча и отношения върху raw tokens и съществуващите sentence spans. spelling използва ordinary forward-index distance 2/limit 10 и показва отделно search disposition, reason и ranked alternatives със source UTF-16 spans. Score е ranking. profile описва typed reading groups, coverage и projection issues; nullable full counts запазват разграничението между непълна и пълна празна оценка.

properNames включва exact typed PROPN supports и maximal compatible groups. Unknown-context advice се включва изрично:

POST /api/v2/analyze-text
{"text":"д-р Алдор.","includeUnknownContextProperNames":true}

Omitted, null и false оставят unknownContextEvaluated false и unresolvedContextTokens null. True включва title, mid-sentence, surname и closed-clause lanes; enabled empty result е празен списък. Graph BaseEvidence отлага unknown-context оценката. completeForEnabledScope и deferredTokenIndices показват обхвата; inferred context е advisory evidence.

Полето е приложимо само към analyze-text. Изрично подадено false или true при друга операция връща 400 option-not-applicable; грешен тип или непознато поле връща 400 invalid-json преди language work. find-forms-in-text запазва обичайния AnalyzeText overload. Request bounds, response budgets, deadlines и cancellation остават приложими. Typed features добавя nullable nameKind като additive serialization change.

Supports са response-local: tokenIndex → occurrence → readingSetIndex → sets entry; completeReadingIndex адресира supportReadings, когато не е null, иначе canonicalReadings. Null support означава неизползван route; празен списък означава изпълнен празен lookup. Display prefix и HTTP wordAnalyses са отделни index spaces.

typed-reading-profile.v1 групира по изрично определения typed tuple. POS/lemma distributions броят displayed readings за всяко Word occurrence с повторенията. Projected group differences са representation observations; контекстният избор изисква отделна оценка. Exact name candidates използват ANY typed PROPN, запазвайки common alternatives в inventory; подкрепените spans оставят интерпретацията и entity identity като отделни задачи.

Контекст, синтактични роли и ограничени проверки — непубликувано

Текущият source checkout добавя context, syntax и validation и в трите формата. Седемте bounded context пътеки и петте основни роли се оценяват автоматично. Оригиналните exact readings, duplicates и UTF-16 spans остават в readingInventory; контекстният избор е отделен overlay, а validation запазва стария diagnostics списък.

POST /api/v2/analyze-text
{"text":"Иван каза че чете.","context":{"includeSubordinateCommaDiagnostics":true}}

Петте independent strict boolean опции са includeAdditionalRoleHeuristics, includeSubordinateCommaDiagnostics, includeFragmentDiagnostics, includeSpacingDiagnostics и includeWordConstructions, всяка с default false. Omitted/null context, празен object и all-false изключват петте opt-in разширения; автоматичните контекстни пътеки, основните роли и bounded validation остават активни. Първите четири опции и includeUnknownContextProperNames остават независими от конструкциите. Същото важи под v1.

Disabled полето е null; наличен изпълнен no-match е празен списък; unavailable prerequisite има изрична причина. Animacy/Transitivity authority липсва и зависимата проверка остава unavailable. Съобщенията са кандидати за преглед; complete описва входните inventories, а не граматическа правилност.

Допълнителните роли отчитат девет groups: unknown-preverbal-attribute, closed-register-title-attribute, closed-adverbials, nominal-possessive-clitic, preposed-object-clitic, special-preposed-dual-and-suppression, closed-da-short-clitic-subpredicate, closed-postverbal-clitic-subject, closed-dative-speech-subpredicate. Candidate count е exclusive брой изведени записи по Rule група; потиснатото предложение дава нула. Contiguous моделите изискват whitespace в едно sentence. Главният predicate index сочи действително изведеното главно сказуемо.

Всеки non-null context, включително празен object, при друга операция връща 400 option-not-applicable. Unknown member и null/string/number вместо boolean връщат 400 invalid-json преди language queue. Bounds, budgets, cooperative deadline и cancellation важат за допълненията.

C# запазва старите извиквания и добавя AnalyzeText(text, includeUnknownContextProperNames, contextOptions, cancellationToken) с четири задължителни аргумента. Nullable Features полетата case, isShortForm, participleKind са additive serialization/equality промяна; JSON Features има 15 полета. Null не задава nominative/long/participle default. Profile v1 изключва новите axes, но existing-axis/flag корекциите могат да променят group/issue counts.

Supports продължават да сочат оригинални Word occurrences и complete reading indices, включително позиции 31/32/33 и равни дубликати. Публикуваният preview 4 е от 19 октомври; тази source партида е след него.

Кандидатни глаголни конструкции — непубликувано

Операцията word-constructions използва точно opaque entryId от lookup-lexical-entries в съществуващото поле text. Не го trim-ва, декодира или заменя с лема; няма fallback към друг owner. Примерите са заявки към текущия source checkout, без обещан записан резултат:

POST /api/v2/lookup-lexical-entries
{"text":"пиша","limit":32}

POST /api/v2/word-constructions
{"text":"<точен entryId от data.entries на първата заявка>"}

POST /api/v1/word-constructions
{"text":"<същият непроменен entryId>"}

Не се подават limit, query, non-null context или includeUnknownContextProperNames със стойност false/true: те са неприложими за тази операция и връщат 400. Важат текущите проверки за непразен вход до 256 UTF-16, строг JSON преди language queue, трите evidenceFormat варианта, response budgets, cooperative deadline и cancellation. limits.scope е scalar-evidence; няма presentation limit или отрязване на own forms/кандидати.

data.statusЗначение
OwnerMetadataUnavailableНяма lexical catalog за exact EntryId заявката.
OwnerNotFoundCatalog е наличен, но точно този идентификатор липсва.
OwnFormsUnavailableOwner е намерен, но complete accepted own forms са недостъпни.
NoApplicableOwn forms са налични; няма приложим supported template, включително при наличен празен набор.

ownForms:null означава недостъпност, а ownForms:[] — наличен празен набор. Заявката връща всички accepted own forms на избрания owner, включително техния ред и дубликати, и всички приложими templates с familyId, targetConstructionTag, parts, basePartIndex и локален ownFormIndex. Query може да съдържа и едночастни templates. Aliases не се сливат по лема.

Текстовото разпознаване се включва отделно с петата опция TextContextOptions.IncludeWordConstructions = true (default false), съответно context.includeWordConstructions:

POST /api/v2/analyze-text
{"text":"😀 писал съм.","context":{"includeWordConstructions":true}}

Същата заявка е налична под /api/v1/analyze-text. Старите overloads и AnalyzeText(text, includeUnknownContextProperNames, contextOptions, cancellationToken) с четири задължителни аргумента се запазват:

CancellationToken token = CancellationToken.None;
LexicalEntryLookup owners = language.LookupLexicalEntries("пиша", 32, token);
if (owners.MetadataAvailable && owners.Entries.Count > 0)
{
    WordConstructionResult candidates = language.GetWordConstructionCandidates(
        owners.Entries[0].EntryId, token);
}
TextAnalysis text = language.AnalyzeText("😀 писал съм.", false,
    new TextContextOptions { IncludeWordConstructions = true }, token);

Disabled TextAnalysis.WordConstructions/data.wordConstructions е null и не извършва owner pairing или own-form acquisition. Enabled резултатът е word-constructions.v1: owners пази owner status и complete own forms, candidates е споделена таблица, а всеки matches запис сочи candidateIndex, оригинални RAW UTF-16 start/length и anchor.tokenIndex/anchor.completeReadingIndex. Text включва само многосъставни templates, anchored в действителните complete exact readings, включително след display индекс 31. Запазва aliases, различни families/targets, дублирани прочити и отделните срещания; кандидат може да няма match. Съвпадението изисква Word части, whitespace и едно sentence, като запазва raw source span.

complete описва придобиването на exact owners/own forms в заявения обхват. При недостъпни own forms на owner резултатите на останалите owners се запазват; съответният owners[].status е OwnFormsUnavailable, ownForms е null и complete е false. Недостъпни pairing/key входове се посочват чрез действителни unavailableReadings references и unavailableTokenIndices. Неподдържан празен lookup без owner pairing остава unavailable token, без измислен reading 0; наличен изпълнен празен обхват е отделен случай и не доказва backend capability извън него. Без annotations Text може да запази реални candidates с entryId:null и валидиран lexemeKey; exact EntryId query остава OwnerMetadataUnavailable. Scoped complete не повишава глобалното HTTP coverage.complete.

Всеки кандидат има acceptedWordForm:false и grammarAuthority:false: template/match не установява lexical compatibility, граматическа правилност или corpus precision. WordConstructionResult отчита productiveReplayAvailable:false и productiveReplayUnavailableReason:"OriginalGenerationSeedNotRetained" означават, че оригиналният generation seed не е запазен; това не е отчет за неуспешна нова генерация. TextAnalysis вече има 15 сериализирани полета, като wordConstructions е additive nullable поле; старият positional constructor/deconstruction се запазва.

Публикуваният preview 4 е от 19 октомври и не включва тази текуща source партида. Този раздел описва consumer договора; не заявява acceptance, review или test резултат за нея.
